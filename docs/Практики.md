# Практики по программной инженерии

Учебный проект — магазин автозапчастей Parts Unlimited. Номера со знаком # ведут к карточкам этого репозитория. В каждой теме сначала повтори действие, затем проверь результат.

## 1.1. Проект

1. На GitHub нажми **+ → New repository**. Введи имя, выбери **Public**, включи **Add README**, нажми **Create repository**. На вкладке **Code** появится первая версия файла.
2. Открой **Wiki → Create the first page**, опиши проект и нажми **Save page**. На вкладке **Projects → New project** создай таблицу для планирования.
3. Доступ для одногруппников выдаётся через **Settings → Collaborators → Add people**. По методичке требуется 3–5 человек. В этом проекте приглашения не отправлялись. Проект принадлежит личному аккаунту. Две рабочие группы указаны в поле «Команда».

**На защите.** Покажи **Code**, **Issues** и **Projects**. В первом лежат файлы и их версии, во втором — задачи, в третьем — план их выполнения.

## 1.2. Wiki

1. В **Wiki → New page** задай название «Начало работы». В тексте поставь ссылку на «Окружение», заполни **Edit message** и нажми **Save page**.
2. Открой «Окружение» → **Edit**. Замени *Team Foundation Server 2018* на *Azure DevOps* и сохрани с пояснением. Нажми **2 revisions**, выбери две версии и сравни строки. [История правки](https://github.com/Arr4nkar/parts-lab/wiki/Окружение/_history).
3. На вкладке **Code → Add file → Create new file** укажи путь, например `docs/events/Январь.md`. Введи текст и нажми **Commit changes**. Для порядка страниц отредактируй боковое меню Wiki (**Add a custom sidebar** или карандаш). В «Документации» ссылки ведут к файлам в основной ветке. [Открыть Wiki](https://github.com/Arr4nkar/parts-lab/wiki).

## 2.0. Тестовые данные

1. Открой [таблицу примеров](../data/tasks.csv). В строке № 6 записаны название, родитель № 3, команда, спринт и оценка. По этим значениям можно восстановить задачу.
2. Через **Issues → New issue → Blank issue** введи название и описание. Для пользовательской истории можно выбрать [форму «История»](https://github.com/Arr4nkar/parts-lab/issues/new?template=story.yml) и заполнить запрос покупателя и критерий проверки. Нажми **Create**. Для назначения себе есть **Assign yourself**. В проекте создано 11 карточек. В списке Issues переключи **Open / Closed**, чтобы увидеть и завершённые примеры.
3. При создании таблицы в **Projects** выбери импорт по поисковому запросу и введи `repo:Arr4nkar/parts-lab is:issue`. Так в план попадут открытые и закрытые карточки. Для GitHub учебный набор собран по сценарию Parts Unlimited. Генератор и сборка .NET из методички предназначены для Azure DevOps. [Исходный проект Microsoft](https://github.com/microsoft/PartsUnlimited).

## 2.1. Спринт и нагрузка

1. Открой [эпик № 1](https://github.com/Arr4nkar/parts-lab/issues/1) и разверни подзадачи. Цепочка ведёт от цели «Обучение продуктам» к функции «Осваиваем дашборды», истории «Новые учебники» и двум задачам. Чтобы собрать такую цепочку, у родителя нажми стрелку рядом с **Create sub-issue → Add existing issue** и выбери дочернюю карточку.
2. В **Projects → План работ → Задачи** столбцы добавляются через **Add field → Create a project field**. Для спринта выбери **Iteration**, для часов — **Number**. Дважды нажми ячейку и внеси значение. У № 6 и № 7 стоит «Спринт 2». [Открыть таблицу](https://github.com/users/Arr4nkar/projects/2/views/1).
3. В учебном расчёте с 21 октября по 6 ноября — 13 будних дней по календарю пн–пт. С 26 по 30 октября сотрудник в отпуске. При 1 ч в день остаётся **(13 − 5) × 1 = 8 ч**. Сначала задачи требовали **5 + 3 = 8 ч**. После уточнения первой задачи — **8 + 3 = 11 ч**. Перегрузка — **3 ч**. Обе задачи оставлены в спринте, чтобы показать проблему. [Задача № 6](https://github.com/Arr4nkar/parts-lab/issues/6) · [Задача № 7](https://github.com/Arr4nkar/parts-lab/issues/7).

## 2.2. Доска и контроль

1. В **План работ → New view → Board** создай доску. Через **View → Column by** выбери «Этап», через **Swimlanes** — «Дорожка». Нажми **Save view**. У «Истории просмотра» стоит «Ускоренная». [Открыть доску](https://github.com/users/Arr4nkar/projects/2/views/2).
2. У столбца **QA → … → Set limit** введи **1**. В **Edit details** укажи критерии проверки. Перетащи туда две карточки — появится **2 / 1**. Верни одну — останется **1 / 1**. [Пример превышения лимита](QA.jpg). Два состояния проверки обозначены полем «Проверка» — «Делаю» и «Сделал».
3. В **Issues → Labels → New label** укажи имя и цвет. У истории № 3 стоят жёлтая метка «данные» и «ux», у задачи № 6 — зелёная «разработка». Их можно назначить через **Edit Labels**. В таблице добавь текстовое поле **Ticket ID**. У истории № 3 стоит **PUL-101**. По нему можно найти задачу из внешней системы. Параметры рабочего процесса в этой версии задаются полями проекта.
4. Для отчёта по задачам с оценкой используй фильтр `has:часы команда:PUL-Web`. Сохрани вид через **Save**. Открой **Insights → New chart → Configure**. Для оси X выбери **Assignees**, для Y — **Sum of a field → Часы**. На диаграмме **8 ч** у Arr4nkar и **3 ч** без исполнителя. Для обзора по спринтам выбери на оси X «Спринт» — получится **11 ч**. [Веб-задачи](https://github.com/users/Arr4nkar/projects/2/views/4) · [Нагрузка](https://github.com/users/Arr4nkar/projects/2/insights/1) · [Сумма по спринту](https://github.com/users/Arr4nkar/projects/2/insights/2).

## 3. Календарь поставки

1. В проекте выбери **New view → Roadmap**. В **View → Dates** задай «Начало» и «Конец», в **Group by** — «Команда». В фильтре введи `has:начало -status:Done` и сохрани вид. На экране останутся три работы. [Открыть календарь](https://github.com/users/Arr4nkar/projects/2/views/3) · [Снимок](Поставка.jpg).
2. В **Issues → Milestones → New milestone** укажи «Команда в отпуске» и дату **27 ноября 2026**. Назначь веху задаче № 9, затем в календаре включи **Markers → Milestone**. [Открыть веху](https://github.com/Arr4nkar/parts-lab/milestone/1).
3. У № 8 открой **Relationships → Mark as blocked by** и выбери № 9. В первоначальном плане отслеживание стояло в спринте 1, данные доставки — в итерации 51, погода — в итерации 50. Поменяй итерации двух интеграций и перенеси отслеживание в спринт 4. [Проверить зависимость](https://github.com/Arr4nkar/parts-lab/issues/8).

| После переноса | Команда | Даты 2026 |
|---|---|---|
| Данные доставки | External integrations, итерация 50 | 9–27 ноября |
| Отслеживание посылки | PUL-Web, спринт 4 | 30 ноября – 11 декабря |
| Прогноз погоды | External integrations, итерация 51 | 30 ноября – 18 декабря |

**На защите.** Без ответа перевозчика сайт не знает статус посылки. Поэтому команда интеграций первой готовит данные, а веб-команда начинает отслеживание со следующего рабочего дня. Это плановые даты. Фактическая готовность отражается в карточках.
